# tia-knowledge — CLAUDE.md

## Purpose

Living knowledge base for the **AleFire-Library** — a Siemens TIA Portal V20 global library
of function blocks and UDTs for pneumatic field devices (valves, diverters, filters, etc.).

Two outputs on every update cycle:

| Output | Consumer |
|--------|----------|
| `docs/` — bilingual MkDocs pages (IT primary, EN) | Engineers reading the wiki |
| `dist/library_manifest.json` — structured JSON of all UDTs + FBs | tia-automation |

## Update Workflow

```
TIA Portal → raw/ → manifest.json → docs/ → site/ → Docker/nginx (LAN)
```

### Step 1 — Export from TIA Portal (requires TIA Portal open)

```bash
uv run python scripts/export.py
# or export manually via TIA Portal VCI → save to raw/
```

After export: **remove all user blocks from the staging project** before committing.

### Step 2 — Ingest: update manifest

```bash
uv run python scripts/ingest.py
```

Walks all of `raw/` recursively for `.scl` and `.udt` files.
Writes `dist/library_manifest.json`.

### Step 3 — Generate docs (Claude Code)

Open this repo in Claude Code and say:

> "Read all files in raw/ and dist/library_manifest.json, then generate full bilingual
> documentation (all 8 sections, Italian primary + English) for each device type."

Claude Code writes `docs/library/<category>/<device>/index.it.md` and `index.en.md`.

### Step 4 — Preview locally

```bash
mkdocs serve
# open http://localhost:8000
```

### Step 5 — Serve on LAN (Docker)

```bash
docker build -t alefires-wiki .
docker run -d -p 8080:80 alefires-wiki
# access from any LAN machine: http://<host-ip>:8080
```

### Step 6 — Commit

```bash
git add raw/ dist/ docs/ library/
git commit -m "chore: update library sources, manifest and docs"
```

- Theme: `mkdocs-material` (red/amber, dark mode toggle)

## Bilingual Structure

`mkdocs-static-i18n` uses **suffix** pattern.

- Always create both `index.it.md` and `index.en.md` when adding a module page
- Italian: primary, full content — written first
- English: full translation — never a stub

## dist/library_manifest.json — Schema Contract

Produced here; consumed by tia-automation's `pipeline/resolve.py`.
**Never remove or rename fields. Bump `manifest_version` on structural changes.**

```json
{
  "manifest_version": "1.0.0",
  "udts": {
    "UDT_SS_Valve": {
      "has_out": false,
      "devices": { "ZSL": {"type": "Bool"}, "ZSH": {"type": "Bool"}, "XY": {"type": "UDT_Solenoid_valve"} }

  "fbs": {

      "ctrl": {"name": "SS_Butterfly_valve", "param": "XV"},
      "sim":  {"name": "SS_valve_simulator",  "param": "XV"}
    }
  }
}
```

## Known Gotchas — TIA Portal V20 / siemens_tia_scripting v1.2.1

1. `LibraryTypeVersion.export()` is **blocked** for global library types via API.
   Workaround: use staging project + `block.export()`.
2. `version.instantiate()` throws `NullReferenceException` for all AleFire-Library types
   when called on a GlobalLibrary proxy. Use `--skip-instantiate` and instantiate manually
   in TIA Portal UI, then re-run.
3. Staging project must be committed in **empty state** between export runs.

## Git Flow

| Branch | From | Merge into | Purpose |
|--------|------|-----------|---------|
| `main` | — | — | Released state; merge from `release/*` or `hotfix/*` only |
| `develop` | `main` | — | Integration; feature branches merge here |
| `feature/<name>` | `develop` | `develop` | One per feature |
| `release/<version>` | `develop` | `main` + `develop` | Stabilisation; bump version, final docs |
| `hotfix/<name>` | `main` | `main` + `develop` | Urgent prod fix |

Commit convention: `type: short description`
Types: `feat` `fix` `chore` `docs` `refactor`

Never commit directly to `main`.

### Gitea Release Process

On every `release/<version>` merge to `main`:

1. Tag `main`: `git tag v<version> && git push origin v<version>`
2. Create release on Gitea from the tag
3. Attach `library/AleFire-Library/AleFire-Library.al20` as downloadable binary asset
4. Back-merge `main` → `develop`
