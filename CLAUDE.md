# tia-knowledge — CLAUDE.md

## Purpose

Living knowledge base for the **AleFire-Library** — a Siemens TIA Portal V20 global library
of function blocks and UDTs for pneumatic field devices (valves, diverters, filters, etc.).

Two outputs on every update cycle:

| Output | Consumer |
|--------|----------|
| `docs/` — bilingual Zensical pages (IT primary, EN), one tree per locale | Engineers reading the wiki |
| `dist/library_manifest.json` — structured JSON of all UDTs + FBs | tia-automation |

## Update Workflow

```
TIA Portal → raw/ → manifest.json → docs/{it,en}/ → site/{it,en}/ → Docker/nginx (LAN)
```

### Step 1 — Export from TIA Portal (requires TIA Portal open)

```bash
uv run python scripts/export.py
# or export manually via TIA Portal VCI → save to raw/
```

After export: **remove all user blocks from the staging project** before committing.

### Step 2 — Ingest: update manifest

```bash
uv run python scripts/ingest.py
```

Walks all of `raw/` recursively for `.s7dcl` files (Simatic SD / VCI format).
Falls back to `.scl` / `.udt` if no `.s7dcl` found (old ExternalSource format).
Writes `dist/library_manifest.json`.

### Step 3 — Generate docs (Claude Code)

Open this repo in Claude Code and use one of these prompts:

**Incremental (normal workflow — only changed/new types):**

> "Read `dist/ingest_delta.json`. If `needs_doc_update` is empty, say so and stop.
> Otherwise for each name in `needs_doc_update`, find its `.s7dcl` + `.libinfo` in `raw/`,
> read them plus `dist/library_manifest.json`, then regenerate full bilingual docs
> (all 8 sections, Italian primary + English) for that type only.
> If `removed` is non-empty, list those names and ask whether to delete their doc pages."

**Full regeneration (first run, or after structural changes):**

> "Read all files in `raw/` and `dist/library_manifest.json`, then generate full bilingual
> documentation (all 8 sections, Italian primary + English) for each device type."

Claude Code writes `docs/it/library/<category>/<device>/index.md` and the mirrored
`docs/en/library/<category>/<device>/index.md` — two locale trees, not suffix pairs.

### Step 4 — Preview locally

```bash
uv run zensical serve --config-file zensical.it.toml
# open http://localhost:8000
uv run zensical serve --config-file zensical.en.toml -a localhost:8001
# open http://localhost:8001
```

Each locale is a separate build/serve instance — there's no single combined dev
server. Full dual-locale + language-switcher check happens via the Docker build
(Step 5).

### Step 5 — Serve on LAN (Docker)

```bash
docker build -t alefires-wiki .
docker run -d -p 8080:80 alefires-wiki
# Italian (default): http://<host-ip>:8080/
# English:           http://<host-ip>:8080/en/
```

### Step 6 — Commit

```bash
git add raw/ dist/ docs/ library/
git commit -m "chore: update library sources, manifest and docs"
```

## Zensical Setup

- Static site generator: [Zensical](https://zensical.org) — successor to MkDocs
  from the Material for MkDocs team. Replaced MkDocs/mkdocs-material because
  MkDocs core has been unmaintained since Aug 2024 and "MkDocs 2.0" breaks the
  whole plugin ecosystem (see git history on `feature/zensical-migration` for
  the full rationale).
- Theme: built into `zensical` itself, `variant = "classic"` (reproduces
  Material for MkDocs' look — red/amber palette, dark mode toggle, no
  separate theme package needed).
- Mermaid diagrams: native support via a `pymdownx.superfences` custom fence
  (configured in both `zensical.*.toml`) — no plugin.
- Navigation: explicit `nav:` list in each `zensical.*.toml` (Zensical has no
  shipped equivalent of `mkdocs-awesome-pages-plugin` yet — tracked upstream
  as ZAP-003 "Navigation as content"). Add new device-type entries there when
  adding a folder.
- Two config files, one per locale: `zensical.it.toml` (default) and
  `zensical.en.toml`. Each has its own `docs_dir`/`site_dir` and an
  `extra.alternate` block linking to the other locale's `/it/` or `/en/`
  build output — this is the workaround for Zensical's i18n suffix-mode
  support still being unshipped (Tier-2 backlog).
- Build output: `site/it/` and `site/en/` (gitignored).

## Bilingual Structure

No i18n plugin — dual language is two independent builds, cross-linked via
`extra.alternate`.

- `docs/it/` and `docs/en/` are two parallel trees, same relative shape, no
  locale suffix on filenames (`index.md`, not `index.it.md`).
- Always create both the `docs/it/...` and matching `docs/en/...` file when
  adding a module page.
- Italian: primary, full content — written first.
- English: full translation — never a stub.
- Internal links must stay within the same locale tree (relative paths, no
  `../en/` or `../it/` crossing between trees — each is built independently).

## Module Page Format — 8 sections (all Claude-generated)

```
1. Overview
2. Main Components
3. I/O Signals
4. Operating Routine
5. Alarms
6. Settings
7. Data Structure      ← Mermaid classDiagram
8. State Machine       ← Mermaid stateDiagram-v2
```

All 8 sections generated by Claude Code from `raw/` source files.
Do not edit `docs/` pages manually — changes will be overwritten on next generation.

## Known Gotchas — TIA Portal V20 / siemens_tia_scripting v1.2.1

1. `LibraryTypeVersion.export()` is **blocked** for global library types via API.
   Workaround: use staging project + `block.export()`.
2. `version.instantiate()` throws `NullReferenceException` for all AleFire-Library types
   when called on a GlobalLibrary proxy. Use `--skip-instantiate` and instantiate manually
   in TIA Portal UI, then re-run.
3. Staging project must be committed in **empty state** between export runs.

## Git Flow

| Branch | From | Merge into | Purpose |
|--------|------|-----------|---------|
| `main` | — | — | Released state; merge from `release/*` or `hotfix/*` only |
| `develop` | `main` | — | Integration; feature branches merge here |
| `feature/<name>` | `develop` | `develop` | One per feature |
| `release/<version>` | `develop` | `main` + `develop` | Stabilisation; bump version, final docs |
| `hotfix/<name>` | `main` | `main` + `develop` | Urgent prod fix |

Commit convention: `type: short description`
Types: `feat` `fix` `chore` `docs` `refactor`

Never commit directly to `main`.

### Gitea Release Process

On every `release/<version>` merge to `main`:

1. Tag `main`: `git tag v<version> && git push origin v<version>`
2. Create release on Gitea from the tag
3. Attach `library/AleFire-Library/AleFire-Library.al20` as downloadable binary asset
4. Back-merge `main` → `develop`
